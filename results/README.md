# `results` — saved outputs

Every file here is a notebook output from the recorded run; no reported number
was recomputed for the repository. The `tables/` folder is the exception: those
CSVs are regenerated by `analysis/reproduce_tables.py`.

| Folder | Produced by | Contains |
|---|---|---|
| `prompted/` | `02`, `03`, `04` | the twelve zero-shot and 5-shot prediction files, plus the prompted-run metrics |
| `lora_search/` | `06_lora_search.ipynb` | the 16-config search manifest, the selected configs, and 15 per-config validation prediction files |
| `stability/` | `07a_stability.ipynb` | the seed 123/456 re-runs of the selected configs |
| `final_eval/` | `07b_final_eval.ipynb` | the frozen test metrics, test predictions, raw generations, and environment record |
| `tables/` | `analysis/reproduce_tables.py` | the tables checked against the report |

`unified_metrics.csv` has an unnamed first column because `04_evaluate.ipynb`
writes `pd.DataFrame(res).T` with the run names as the index. The entries are
the run labels (`S zero-shot`, `D seed42`, and so on); `S` is structure and `D`
is direct.

The structure environment record shows `torch 2.11.0+cu128`; the final-eval
record shows `+cu130`. Both ran on a Tesla T4. The CUDA build follows whatever
the Colab runtime provided on that day and does not change the computation.
The structure runs for seeds 789 and 1011 were completed on Kaggle and have no
environment record in this archive.

## `lora_search/`

`search_results.csv` has one row per configuration: 8 per pipeline. Columns
include `r`, `alpha`, `lr`, `epochs`, `steps`, `train_loss`, `macro13`,
`macro14`, `NoFinding`, `valid14`, `usable_any`, and runtime. Selection is the
highest validation macro13, with ties broken by lower rank, fewer epochs, and
lower alpha.

`selected_configs.json` records the winner per pipeline, its validation score,
and the absolute adapter path from the Colab session. Direct selected
`r=16, alpha=32, lr=2e-4, epochs=2`; structure selected
`r=32, alpha=32, lr=2e-4, epochs=2`. The file is the one written by
`06_lora_search.ipynb` and recovered from the Drive download; it is identical to
the `selected` block of `final_eval/environment_07b.json`, which records the
selection at run time.

`<pipeline>/<config>/val_predictions.csv` holds per-report validation output for
that configuration. Fifteen of the sixteen configurations have this file; see
*Missing files* below.

The training adapters themselves are not included. Individual weight files are
47–194 MB, and several exceed GitHub's 100 MB limit; they are regenerated by
`06_lora_search.ipynb`.

## `stability/`

`stability_results.csv` and `stability_summary.csv` record retraining the two

## Column conventions

Prediction tables carry one pair of columns per finding, in this order:

```
No Finding, Enlarged Cardiomediastinum, Cardiomegaly, Lung Lesion, Lung Opacity,
Edema, Consolidation, Pneumonia, Atelectasis, Pneumothorax, Pleural Effusion,
Pleural Other, Fracture, Support Devices
```

- `truth_<finding>` is the silver label: `1.0`, `0.0`, `-1.0`, or empty.
- `pred_<finding>` is the parsed output in `1`, `0`, `-1`, `NaN` form. For
  structure runs the parse is applied to `raw`: `present`→`1`, `absent`→`0`,
  `uncertain`→`-1`, `not_mentioned`→`NaN`.
- `raw` is the model's verbatim output. The prompted direct files do not have
  it; every prompted structure file does, and so do the fine-tuned direct runs.
- `id` is the OpenI report identifier and is unique within a split.

Scoring does not use `truth_<finding>` as written. The analysis script maps `-1`
to missing and empty to `0`, and counts only a predicted `"1"` as positive.

`valid14` is the share of reports whose output the parser could read as all 14
fields, including fields whose value is `NaN` or `not_mentioned`; `usable_any`
is the share with at least one readable field. A failed or invalid generation
contributes no fields and is still scored.

## Missing files

One LoRA-search validation prediction file was absent from every download:

- `structure/structure_r16_a16_lr0.0002_ep1_s42/val_predictions.csv`

It is not a selected configuration. Its validation macro13 remains in
`search_results.csv`, which is the source for the matched-configuration table.
The fifteen files that are present reproduce their manifest scores exactly; the
analysis script asserts this.
